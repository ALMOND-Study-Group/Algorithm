### 1. 변수와 자료형
```java
byte   (1바이트) : -128 ~ 127
short  (2)       : -32,768 ~ 32,767
int    (4)       : -2^31 ~ 2^31-1 (약 ±21억) ← 정수 기본
long   (8)       : 끝에 L 붙임 (ex. 100L)

float  (4)       : 끝에 F 붙임 (ex. 3.14F)
double (8)       : 실수 기본

char   (2)       : 한 글자, ''로 감쌈, 유니코드 지원 ('A', '가')
boolean(1)       : true / false

String            : 참조형이지만 기본형처럼 씀 ("문자열")
```

- 변수 선언: `자료형 변수명;`  
- 초기화: `int age = 25;`
- 상수: `final double PI = 3.14;`

여기서 부동수소점 오차에 대해서 이야기를 해보자
**tip!.** 컴퓨터는 0.1 같은 10진수 소수를 2진수로 정확히 표현할 수 없기 때문에 생기는 미세한 오차

**이게  왜 생김?**

```java
System.out.println(0.1 + 0.2);   // 기대값 0.3
// 실제 출력 → 0.30000000000000004
```

- `float`, `double`은 IEEE 754라는 국제 표준으로 저장됨
- 10진수 0.1은 2진수로 무한소수가 됨 (0.00011001100110011… 무한 반복)
- 컴퓨터는 유한한 비트(32bit 또는 64bit)만 사용 → 끝자리를 반올림해서 저장
- 그래서 실제 저장된 값은 0.1보다 아주 조금 큰 값이 됨
- 이런 미세한 오차들이 덧셈·뺄셈 시 누적 → 우리가 예상한 결과와 달라짐

### **대표적인 오차 예제 (자바의 정석에 자주 나오는 코드)**

```java
System.out.println(1.0 - 0.9);        // 0.1 기대 → 0.09999999999999998
System.out.println(0.1 * 10 == 1.0);   // false !!!
System.out.println(0.1 + 0.2 == 0.3);   // false !!!
```

### **실무에서 절대 하면 안 되는 코드**
```java
if (price == 1000.0) { ... }           // 위험!
if (total == 999.99) { ... }           // 위험!
```

### 2. 연산자
- 산술: `+ - * / %`
  - `/` : 정수끼리 나누면 몫만 (5/2 = 2)
  - `%` : 나머지
- 증감: `++`, `--` (전위: 먼저 증감, 후위: 나중에 증감)
- 비교: `== != > < >= <=`
- 논리: `&&`(and), `||`(or), `!`(not)
- 삼항: `조건 ? A : B`
- 대입: `= += -= *= /= %=`

**tip!.** 여기서 쉬프트 연산자는 덧셉보다 우선순위가 낮다.

### 3. 조건문
```java
if (조건) {
    // 실행
} else if (조건2) {
    // 실행
} else {
    // 실행
}

switch (변수) {            // 정수, char, String 가능 (자바7부터 String 가능)
    case 값1: 
        실행문; 
        break;             // break 없으면 아래 case까지 쭉 실행 (fall through)
    case 값2: 
        실행문; 
        break;
    default: 
        실행문;
}
```

### 4. 반복문
```java
// for
for (int i = 0; i < 10; i++) {
    System.out.println(i);    // 0~9
}

// while
int i = 0;
while (i < 10) {
    System.out.println(i++);
}

// do-while (최소 한 번은 실행)
int i = 0;
do {
    System.out.println(i++);
} while (i < 10);

// 향상된 for문 (배열, 컬렉션용)
int[] arr = {1,2,3,4,5};
for (int num : arr) {
    System.out.println(num);
}
```

- `break;` (즉시 현재 반복문/스위치 완전 탈출)
- `continue;` (이번 회차만 스킵하고 다음 회차로 바로 감)

### 5. 배열 (Array) --> 개인적으로 중요하게 생각하는 곳
```java
// 선언
int[] arr;                    // 추천
int arr2[];

// 생성
arr = new int[5];             // {0,0,0,0,0}으로 초기화
int[] arr = new int[]{1,2,3,4,5};
int[] arr = {1,2,3,4,5};      // 선언과 동시에만 가능

// 사용
arr[0] = 10;
System.out.println(arr[1]);
System.out.println(arr.length);  // 5 (길이)

// 2차원 배열
int[][] matrix = new int[3][4];       // 3행 4열
int[][] matrix = {{1,2}, {3,4}, {5,6}}; // 가변 배열도 가능
```

| 항목                      | 내용                                                         | 핵심 포인트 (한 줄씩 기억하세요)                             |
| ------------------------- | ------------------------------------------------------------ | ------------------------------------------------------------ |
| **배열은 객체다**         | `int[] arr = new int[5];` → **Heap에 객체로 생성**된다       | 배열도 참조형! → **참조 변수는 Stack, 실제 데이터는 Heap**   |
| **배열 객체의 실제 구조** | Heap 안에 <br />1. 객체 헤더 (Mark Word + Klass Pointer) <br />2. **length 필드** (배열 길이) <br />3. 실제 데이터 (연속된 메모리) | `arr.length`는 필드 아님 <br />→ JVM이 내부에 저장해 둔 값 (상수처럼 읽기만 가능) |
| **메모리 배치 예시        |                                                              |                                                              |
| **Stack vs Heap**         | java<br>void method() {<br>    int[] arr = new int[1000000];  // Stack X → Heap O<br>    int x = 10;                    // Stack O<br>}<br> | 로컬 변수 arr은 Stack에 참조값(주소)만 저장                  |
| **다차원 배열의 진실**    | `int[][] arr = new int[3][4];` //행열순서임 <br />→ 실제로는 **배열의 배열** <br />→ Heap에 1차원 배열 4개(각각 new int[4])가 생기고, 바깥 배열은 그 4개의 참조를 가짐 | 가변 배열 가능! `int[][] arr = {{1,2}, {3,4,5}, {6}};` 완전 OK |
| 배열 복사 **방식**        | **1. 얕은 복사 (참조 복사) `int[] b = a;` → 같은 객체 가리킴 <br />2. 깊은 복사 `System.arraycopy()`, `clone()`, `Arrays.copyOf()`** | 실무 99%는 `Arrays.copyOf(arr, arr.length)` 사용             |
| **배열 초기화 값**        | `java<br>int[] a = new int[5];     → {0,0,0,0,0}<br>boolean[] b = new boolean[5]; → {false...}<br>참조형 배열 → null<br>` | JVM이 자동으로 기본값 채워줌                                 |
| **배열의 한계**           | 1. 길이 고정 (생성 후 못재할당만 가능) <br />2. 인덱스 범위 체크 O → `ArrayIndexOutOfBoundsException` 발생 (성능 약간 손해)<br />3. 배열의 길이를 변경할려면 다시 생성 후 복사한다. | 그래서 실무에서는 **ArrayList**가 훨씬 많이 쓰임             |



### 자바 배열 복사 한눈에 정리

| 방식                             | 코드 예시                                 | 결과                                  | 실무 추천도         |
| -------------------------------- | ----------------------------------------- | ------------------------------------- | ------------------- |
| **참조 복사** (얕은 복사)        | `int[] b = a;`                            | 같은 배열 가리킴 (수정하면 같이 바뀜) | ★☆☆☆☆ 절대 금지     |
| **System.arraycopy** (가장 빠름) | `System.arraycopy(a, 0, b, 0, a.length);` | 깊은 복사, 성능 최고                  | ★★★★★ 실무 최강     |
| **Arrays.copyOf** (가장 편함)    | `int[] b = Arrays.copyOf(a, a.length);`   | 깊은 복사, 코드 가장 짧음             | ★★★★★ 코테+실무 1등 |
| **clone()**                      | `int[] b = a.clone();`                    | 깊은 복사 (배열에만 안전)             | ★★★☆☆ 가끔 씀       |
| **for문 직접 복사**              | 하나씩 b[i] = a[i]                        | 깊은 복사, 느리고 장황                | ★☆☆☆☆ 비추천        |

### 예를 들어서

```java
// 1위 (가독성 최고)
int[] copy = Arrays.copyOf(original, original.length);

// 2위 (성능 최고, 대량 복사 시)
int[] copy = new int[original.length];
System.arraycopy(original, 0, copy, 0, original.length);
```
